## 项目背景

下载文件夹是 Mac 上最容易"烂掉"的地方：截图、PDF、图片、文档堆在一起，每次打开都要翻半天。市面上的文件管理工具要么大而全、要么需要联网上传、要么深度介入用户的整理习惯，反而制造新的摩擦。

Smoother 想做的不是又一个文件管理器，而是一个"安静地帮你把下载文件夹抚平"的菜单栏小工具——只盯着 `~/Downloads` 根目录，来了新文件就按规则归位，其余时间隐形。本地运行、零联网、零账号，下载即用。

## 目标用户

- **重度下载用户**：每天产生大量截图、PDF、设计稿，懒得手动归档
- **隐私敏感用户**：不希望文件被上传到云端做分类，坚持本地处理
- **整理强迫症患者**：希望下载文件夹始终保持干净，但又不想放弃对手动整理子文件夹的控制权
- **Mac 轻量工具爱好者**：偏好菜单栏常驻、随用随走的小工具，而非臃肿的图形界面应用

## 核心功能

### 1. 自动监控下载文件夹
- 菜单栏常驻（扫帚图标），点击"开始监控"即生效
- 后台线程**每 3 秒轮询**一次 `~/Downloads` 根目录
- 维护已知文件集合，仅对新出现的文件触发整理，不打扰已有文件
- 只扫描根目录，**不递归**子文件夹——用户手动整理的子目录完全不受影响

### 2. 按规则自动移动和重命名
- 内置规则引擎：按文件扩展名匹配，命中即移动到目标文件夹并重命名
- 默认规则：`jpg / png / pages / pdf` → `~/Downloads/Smoother整理`
- 目标文件夹不存在时自动创建
- 移动采用 `shutil.move`，同卷为 rename、跨卷自动 copy+delete
- 目标重名时自动追加后缀（`_1`、`_2`…），**绝不覆盖**已有文件

### 3. 自定义命名模板（config.txt）
- 模板从脚本同目录的 `config.txt` 读取，启动时加载
- 文件缺失或为空时自动回退默认模板 `{date}_{original}`
- 支持三个占位符：

  | 占位符 | 含义 | 示例 |
  |---|---|---|
  | `{date}` | 当前日期 YYYY-MM-DD | `2026-08-28` |
  | `{original}` | 原文件名（不含扩展名） | `photo` |
  | `{counter}` | 重名时自动递增的序号，从 1 开始 | `1` → `2` → `3` |

- 示例：模板 `{date}_{original}_{counter}` 会生成 `2026-08-28_photo_1.jpg`

### 4. 自动整理日志 CSV
- 每次成功移动后，在目标文件夹下追加一条记录到 `整理日志.csv`
- 四列：`原文件名, 新文件名, 目标文件夹, 整理时间`
- 文件不存在时自动创建并写入表头
- 使用 `utf-8-sig` 编码，Excel / Numbers 打开中文不乱码
- 仅记录成功移动的文件，跳过的不计入

```
原文件名,新文件名,目标文件夹,整理时间
photo.jpg,2026-08-28_photo.jpg,/Users/banban/Downloads/Smoother整理,2026-08-28 14:30:05
report.pdf,2026-08-28_report.pdf,/Users/banban/Downloads/Smoother整理,2026-08-28 14:31:12
```

### 5. 一键设置文件夹图标
- 菜单中"设置文件夹图标"项
- 依次弹出两个系统选择面板：先选目标文件夹（仅文件夹），再选图片（限定 png / jpg / jpeg）
- 调用 `NSWorkspace.setIcon:forFile:options:` 将图片设为文件夹自定义图标
- 成功发送"图标已应用"系统通知，失败则打印错误

## 技术栈

- **Python 3**：主体语言
- **rumps**：macOS 菜单栏应用框架（基于 PyObjC）
- **AppKit / PyObjC**：`NSOpenPanel` 选择面板、`NSImage` 图片加载、`NSWorkspace` 图标写入、`NSApp` 应用激活
- **标准库轮询**：`os.scandir` + `threading` + `threading.Event` 实现定时扫描与优雅停止
- **标准库 csv**：整理日志读写
- **标准库 dataclasses**：规则数据结构

> 不依赖 watchdog 等事件驱动库，不依赖任何联网组件，全部本地运行。

## 创新点

- **关注微小摩擦，不做大而全的文件管理**：只解决"下载文件夹乱"这一个具体痛点，克制地保持小而专
- **本地运行，无需联网，保护隐私**：文件不离开本机，没有账号、没有云同步、没有数据上传
- **只监控下载根目录，不打扰用户手动整理的子文件夹**：递归监控会让用户自己建的归档目录也被反复扫描，Smoother 主动避开这一点，把"自动整理"和"手动整理"的边界划清楚

## 开发过程

1. **方案选型**：最初采用 `watchdog` 的事件驱动方案，期望用 FSEvents 实现毫秒级响应
2. **遇到阻碍**：在新版 macOS + watchdog 6.0 环境下，FSEvents 报 `Failed creating fsevent stream`，事件流创建失败，且异常发生在 emitter 线程、主线程无法捕获；叠加 Python 3.14 兼容性问题，事件驱动路线在 MVP 阶段跑不通
3. **路线切换**：果断放弃事件驱动，改用**标准库定时轮询**——后台线程每 3 秒 `os.scandir` 一次，对比已知文件集合做差集，稳定可靠、零外部依赖
4. **MVP 跑通**：菜单栏常驻 + 启停监控 + 规则移动 + 模板重命名，最小可用版本完成
5. **逐步增强**：在轮询骨架上叠加 CSV 整理日志、文件夹自定义图标、`config.txt` 外部模板（支持 `{counter}` 占位符），每一步都保持向后兼容

> 从"高大上的事件驱动"退回到"朴素的人肉轮询"，换来的是稳定、可调试、零依赖——这正契合 Smoother"抚平摩擦"的产品哲学。

## 后续计划

- **可视化规则管理界面**：用菜单栏弹窗或独立窗口管理扩展名 → 目标文件夹的映射，替代手改代码
- **基于来源网站的分类保存**：结合 Safari/Chrome 下载历史，按下载来源域名分文件夹归档

## 运行方式

### 环境准备

```bash
# 安装依赖（rumps 会自动带上 PyObjC）
pip install rumps
```

### 启动应用

```bash
python3 smoother.py
```

菜单栏将出现扫帚图标，菜单结构如下：

```
开始监控
停止监控
────────
设置文件夹图标
────────
退出
```

### 使用流程

1. 点击 **开始监控**，开始轮询 `~/Downloads`
2. 向下载文件夹拖入或下载新文件（如 `photo.jpg`）
3. 软件自动移动到 `~/Downloads/Smoother整理` 并重命名为 `2026-08-28_photo.jpg`
4. 目标文件夹下生成 `整理日志.csv` 记录本次整理
5. 点击 **停止监控** 暂停，**退出** 结束程序

### 自定义命名模板

编辑脚本同目录下的 `config.txt`，**只放一行模板**（整个文件内容会被当作模板，不要写注释或多行）：

```
{date}_{original}
```

其他可选模板（替换上面那一行即可）：

```
{date}_{original}_{counter}
```

```
{original}
```

修改后重启程序生效。文件删除或留空时自动回退默认模板 `{date}_{original}`。

### 自定义整理规则

编辑 `smoother.py` 中的 `self._rules` 列表，添加 `Rule`：

```python
self._rules = [
    Rule(extensions=["jpg", "png", "pages", "pdf"],
         destination="~/Downloads/Smoother整理"),
    Rule(extensions=["zip", "dmg"],
         destination="~/Downloads/安装包"),
    Rule(extensions=["doc", "docx", "txt"],
         destination="~/Downloads/文档"),
]
```

### 设置文件夹图标

1. 菜单点击 **设置文件夹图标**
2. 第一层面板：选择目标文件夹（仅允许选文件夹）
3. 第二层面板：选择图片（仅允许 png / jpg / jpeg）
4. 成功后收到"图标已应用"通知，Finder 中该文件夹即显示自定义图标
